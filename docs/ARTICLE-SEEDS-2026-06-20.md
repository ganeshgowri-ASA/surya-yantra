## Seed 1 — Making Scientific Web Tools Discoverable

**Proposed title:**
> "Structured Data and SEO for Open-Source Scientific Instrumentation Platforms:
A Case Study with Surya Yantra's IEC-Compliant PV IV Curve Tracer"

**Target venue:** *MDPI Software* or *Journal of Open Source Software (JOSS)*

**Research narrative:**

Open-source scientific tools are routinely under-discovered because they treat
web presence as an afterthought. This article uses Surya Yantra as a worked
example — a Next.js + Electron platform hosting real IEC-standard measurement
logic — to demonstrate a reproducible SEO checklist for research software:

1. **schema.org `SoftwareApplication` JSON-LD** with `codeRepository`,
   `license`, and `author` fields that Google Scholar, Semantic Scholar, and
   OpenAlex can ingest.
2. **Per-route OpenGraph and Twitter card metadata** via Next.js App Router
   `layout.tsx` wrappers, compatible with `'use client'` page components.
3. **`robots.ts` + `sitemap.ts`** in the Next.js App Router convention,
   blocking `/api/` while declaring all UI routes.
4. **Canonical URL strategy** when the same app is served from a Vercel
   preview URL and a custom lab domain (`surya-yantra.srishtipvlab.in`).
5. **IEC standard keywords** as `<meta name="keywords">` — ensuring that
   queries like "IEC 60891 open source" or "IV curve tracer HJT" surface the
   platform in niche technical searches.

## Seed 2 — Coherent Metadata Across a Multi-App Research Ecosystem

**Proposed title:**
> "Brand-Coherent SEO Architecture for Multi-App Scientific Platforms:
Lessons from the Anahata Srishti ASA Ecosystem
(antaryami-os · SolarLabX · ShilpaSutra · Surya Yantra)"

**Target venue:** *Software: Practice and Experience* (Wiley)

**Research narrative:**

The ASA platform ecosystem deploys six or more Vercel-hosted Next.js
apps under the same organisational identity (Anahata Srishti / Srishti PV Lab).
Without coordination, each app's `metadataBase`, `openGraph.siteName`, and
`twitter.creator` fields drift independently, breaking cross-app citation graphs
and preventing Google from surfacing the organisation as a Knowledge Panel.

This article proposes a `@asa/seo-config` shared package pattern:

```ts
// packages/seo-config/src/index.ts
export const asaMetadataBase = new URL('https://anahatasrishti.in');
export const asaOrganisation = {
  '@type': 'Organization',
  name: 'Anahata Srishti Advancements',
  url: 'https://anahatasrishti.in',
  sameAs: [
    'https://github.com/ganeshgowri-ASA',
    'https://www.linkedin.com/company/anahata-srishti',
  ],
};
```

Each app composes its own `SoftwareApplication` JSON-LD block by extending
`asaOrganisation`, ensuring that `sameAs` linkage propagates across all apps
and that Google's entity graph recognises Surya Yantra, SolarLabX, ShilpaSutra,
and antaryami-os as products of a single identifiable research entity.

**Blocked on:** organisation-level domain (`anahatasrishti.in`) DNS + website — confirm
with team before publishing.
