## Seed A — "Open-Source IEC-Compliant PV Correction Pipeline: Architecture, Tests, and Reproducibility"

**Motivation:** The four IEC 60891:2021 correction procedures (P1–P4), the IEC 60904-7 SMMF, and the IEC 61853-2 Martin-Ruiz IAM are individually well-documented in standards, but no open-source reference implementation exists that implements all six transformations with:
- a clean TypeScript API,
- a 46-test CI suite with numeric regression tests against the standard's worked examples, and
- an HTTP pipeline endpoint with abort-on-invalid-factor logic.

Surya Yantra's `apps/web/lib/` fills that gap. Publishing this as a journal article (or IEEE PVSC conference paper) would let other PV labs adopt the correction engine without rewriting it.

**Engineering hook (recent commits):**
- `61ae9b0` — IEC correction engine + 46 Vitest tests, all passing
- `3031b05` — `/api/corrections/apply` endpoint added to web app

**Proposed outlet:** *Progress in Photovoltaics: Research and Applications* (Wiley, IF 8.7), or IEEE PVSC 2026 proceedings.

**Narrative arc:**
1. Why reproducible STC corrections matter for NABL accreditation and energy yield comparisons.
2. Survey of existing open-source tools (pvlib-python, RdTools) and the gap in server-side TypeScript.
3. Algorithm implementation decisions (union-grid trapezoidal SMMF, abort-on-wild-factor).
4. Validation against IEC 60891:2021 Annex A worked examples.
5. Integration with the 75-module test bed (MUX + e-load).

**Estimated effort:** 3 writing days + 1 review cycle. Blocker: IEC 60891:2021 Annex A numerical comparison table (data already in codebase as Vitest fixtures).

**Suggested filename:** `drafts/open-source-iec-correction-pipeline.md`

## Seed B — "ShilpaSutra Parametric CAD × Surya Yantra MUX: Co-Designing Hardware and Software for Reproducible PV Test Beds"

**Motivation:** Most PV test bed papers describe either the hardware or the software separately. The Srishti lab's approach — using ShilpaSutra parametric CAD for the 19" MUX chassis and Surya Yantra software for the control layer, developed in the same monorepo ecosystem — enables a design-time link between relay count, chassis dimensions, and firmware register map. This co-design narrative is novel.

**Engineering hook (sibling repos):**
- **ShilpaSutra** (issue #40): parametric CAD for the 6U MUX chassis, with slot dimensions driven by relay footprint parameters.
- **surya-yantra** (issue #63): MUX firmware not yet committed; the article would document the register map and chassis-to-firmware parameter flow.
- **GanitaSutra-v0** (issue #39): IEC 60891 algorithm prototyping that fed into the surya-yantra correction engine.

**Proposed outlet:** *Solar Energy* (Elsevier, IF 6.3), hardware-software co-design track.

**Narrative arc:**
1. Motivation: why MUX test beds are bespoke and expensive.
2. ShilpaSutra: parametric CAD that outputs DXF for laser cutting + BOM for procurement.
3. Surya Yantra: firmware + software that consumes the chassis's relay count as a configuration parameter.
4. Closed-loop validation: commissioning checklist from HARDWARE-SETUP.md §7 verified against CAD-derived expected values.
5. Cost and reproducibility: ₹12L build cost, full BOM open-sourced.

**Estimated effort:** 4 writing days + ShilpaSutra CAD figure exports (blocked by issue #60 — hardware/schematics/ missing).

**Suggested filename:** `drafts/shilpasutra-surya-yantra-codesign.md`
